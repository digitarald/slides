ACT II — TASKS

How tools trigger tasks

Any tool call can become a long-running task. The client opts in, the server responds immediately, and progress flows back as notifications.

1

Client sends tools/call with task metadata

{ "method": "tools/call", "params": { "task": { "ttl": 3600000 } } }
2

Server returns CreateTaskResult immediately

Task ID assigned, status: working. Client is unblocked.

3

Server emits notifications/tasks/status

Real-time progress: "847 of 1,204 spans indexed"

4

Task hits input_required — pauses for human

Decision only a human can make. Task waits, then resumes.

5

Client fetches result via tasks/result

Same tool call result format. Survives disconnects—close VS Code, come back, still running.

STATES

working
input_required
completed

cancelled

The state nobody builds for: input_required — the task pauses until the human decides, then resumes. That’s not fire-and-forget, that’s collaboration.
