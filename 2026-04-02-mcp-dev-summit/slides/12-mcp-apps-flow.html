How MCP Apps render

Tools declare UI resources. The host fetches HTML, renders it in a sandboxed iframe, and bridges communication via postMessage.

1

Tool declares UI metadata

"_meta": { "ui": { "resourceUri": "ui://charts/dashboard" } }
2

Host fetches HTML resource from server

MIME: text/html+mcp — client validates before rendering

3

Rendered in sandboxed iframe in chat

No parent access, restricted DOM, all tool calls logged and auditable

4

Bidirectional JSON-RPC via postMessage

// Inside iframe — call back to server
const result = await bridge.callServerTool('drill_down', { traceId })

+ Sampling: The server can call sampling/createMessage to reason about your data using the client's LLM. Server orchestrates, client executes—no API keys needed on the server.

Graceful degradation: Clients declare support via capabilities.experimental.mcpApps. Unsupported clients never see the _meta.ui field. Servers can add fallback tools to expose data as text.
